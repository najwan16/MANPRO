# Simulation Design — System Analyst

## Company and problem

**PT Nusa Digital Solusi** is fictional. Project Manager **Dina Prameswari**, stakeholder **Rani (Office Operations Lead)**, project **Meeting Room Booking System**. Current spreadsheet process allows double booking; user plays Junior System Analyst.

## Free task (3 structured decisions, ~5 minutes)

1. Select functional requirement relevant to double booking.
2. Assign business priority.
3. Select test to validate requirement.

Users get actual field-level feedback and task score; no certification or broad readiness inference.

## Paid Task 1 — Requirements Register (30% of final score)

Classify four stakeholder statements: availability search = functional; response within 2 seconds = nonfunctional; payroll = out-of-scope; reject overlapping schedule = functional. Choose prevention of overlap as MVP priority. Five fields at 20 points each. Peserta juga menulis memo keputusan ke tim developer (≥25 karakter), disimpan sebagai bukti tulisan asli dan tidak auto-skor. Output Requirements Register dengan klasifikasi, prioritas, dan memo peserta.

## Paid Task 2 — User Story Specification (40%)

Construct actor (staff), action (check available and request at specific time), business benefit (avoid schedule conflicts), and two acceptance criteria (search availability and reject overlapping bookings). Distractors include theme color and payroll export. Score components: actor 15, action 25, benefit 20, criteria 40 (20 per correct selected, -10 for each irrelevant selection, minimum 0 for that field). Peserta juga **wajib menulis satu user story dengan kalimat sendiri (≥30 karakter)** sebagai artefak asli yang disimpan di V1/V2; bagian tulisan bebas ini **tidak dinilai otomatis**. Output generated user story, AC list, dan naskah peserta. Optional diagrams.net external link for manual modeling, not used in scoring.

## Paid Task 3 — Requirement Validation Log (30%)

Resolve "segera" ambiguity, clarify numeric SLA, define authorization and conflict resolution for priority bookings, identify testable approval criterion, and log change impact. Five fields at 20 points. Peserta juga menulis satu pertanyaan klarifikasi ke stakeholder (≥25 karakter), tidak auto-skor. Output Validation Log dan pertanyaan asli peserta.

## Actual delivered experience

- Workplace brief + decision-based editor + built-in live artifact preview.
- Save draft locally; submit V1 for graded feedback; revise original decisions; submit V2.
- Each version graded using same case/rubric; score can stay equal or decrease.
- Report and exported Markdown portfolios reflect exact decisions submitted.

## Limitations

Structured input is controlled, so it measures scenario-specific choices/recognition and basic requirements reasoning, **not** unrestricted professional document-writing competence. The build does not programmatically integrate external SaaS tools or assess external diagrams. Validate with practitioners and add meaningful written artifacts only after developing trustworthy rubrics.
